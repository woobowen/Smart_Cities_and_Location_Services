# A 的开发结果裁决接口

本接口展开已登记的 [首轮计划](a_candidate_plan.json) 与 [机器合同](../../config/goal3/contract.json)，不增加候选、指标或数据范围。A 只消费完整 `G3_DEVELOPMENT` 的当前有效结果与对应 C 回执；没有接受 G0、S0 或组合的预设结论。首轮候选/合同范围已由 [C 回执](independent_c/contract_split_receipt.json) 核查；这不是对尚未执行产物的核验，也不是新的用户批准。

## 1. 进入裁决前的共同检查

每批新结果至少提供：run ID、代码/合同/分区/原始输入/策略定义哈希、完整 240 个原始记录的有序范围、原始与派生对象绑定、逐记录比较、聚合表、失败清单、实际成本、C 检查对象与回执哈希。不得只给摘要中的 `PASS` 或候选的自报分数。

结果与回执必须对应同一产物；缺失、重复或额外记录、源版本变动、未关闭工程问题均先进入 B-Repair。修复后使用新 run、使受影响旧结果失效、由 C 核验新目标，才能恢复本决策；不能把技术失败作为研究负结果。旧 G2 表只作问题来源和一致性参照，不能代替这批 G3 输出。

共同 S/D 保护逐记录应用于固定 R0 和当前 incumbent：覆盖的原始点身份集合不丢失；在相应比较方已覆盖集合上的候选最大几何误差不超过比较方最大值加固定数值余量；原有非空记录及原始窗口身份不丢失；原始断点跨越为 0。发布策略的 P 实际误差同时满足 5 工作米预算。任一记录失败都不允许跨记录平均抵消。

S/D 的严格收益至少是增加一个共同覆盖原始点，或某条可比较记录的同集合最大误差下降超过既定余量。`null` 不填 0、不作为几何改善。记录保留点数、方向删除量、长度与成本均单列，不能替代主要读数。新增覆盖点的误差和短段信息必须另报。

## 2. A1：父项、参考与已有单项

先核对完整的 `R0、S0、S_POINTS2、S_LENGTH0、D60、P2、P10`，不能仅凭最早返回的有利结果开始选择。消费顺序如下。

1. 核对 R0 工程正确性及已登记参考身份，初始化 incumbent 为 R0。R0 无法验证时暂停依赖它的比较并修复。
2. 消费 S 的四项共同对照 `R0 / S_POINTS2 / S_LENGTH0 / S0`。保存两个单独放宽项、二者组合及两个移除方向的逐记录比较。S0 仅在相对 R0 全保护通过且有严格收益时接受；否则保持 R0并记录实际失败或无收益。没有自动预定 S0。
3. 执行去除组件检查：若 `S_POINTS2` 或 `S_LENGTH0` 与已接受 S0 的完整读数等价，优先登记可移除组件及较简单的已登记父方案；若缺少等价证据，不用相近均值称冗余。首轮已有 G2 证据显示二者各有覆盖贡献，但是否沿用仍由当前结果决定。不得由此临时构造未登记的“单过滤项 + G0”。
4. 消费 D60 独立作用，列出全部改善、失败和不变记录，并按预先存在的原始时间分组汇总。D60 已有真实退化，角色是历史单项重算与 G0 的机制依据，不进入无条件部署短名单。不能因均值改善把失败忽略，也不能用 S0 新增的其他窗口冲淡旧窗口退化。
5. 消费 P2、P10 的 P 专项比较及 raw 几何描述。按第 5 节应用相同上游、相同完整 P 输入及共同误差预算；禁止将更低自身 DP 误差称为压缩进步。

S0 或其简化的已登记父项是否被接受、D/P 的负结果和各项实际数据范围均写入 A1 裁决。仅仅“实际运行完 7 个策略”不是研究裁决。

## 3. A2：唯一新分组规则 G0

G0 的分组定义已经固定：完整原始时间序列所有相邻差均满足 `0 < dt <= 30` 秒时 direction=60；存在非正差、超过 30 秒、无可计算差分或诊断不可用时 direction=35。不得根据 A1 新结果修改 30 秒、分组数量、适用记录 ID 或组内参数。

先独立比较 `G0|R0`。只有完整 240 条工程核验通过、所有共同保护通过且至少一条严格收益，才能把 G0 登记为“支持进行组合的父项”。任一保护失败时 G0 为实际权衡/约束拒绝；全部保护通过但无严格收益时为 `NO_DEMONSTRATED_GAIN`。两者均撤回计划中的 S0_G0 执行准入，不在本轮接口里增加新的补救机制。

G0 通过相对 R0 的单项准入，不代表它可替代当前 incumbent。替换仍需 `G0|incumbent` 满足同样保护和收益；例如较弱覆盖不能以更小误差抵消。不可比较就保留当前 incumbent，G0 的独立价值完整保留。

S0_G0 的执行同时要求 S0 与 G0 均是当前版本已经独立支持的父项。若 S0 被证实与更简单父项等价，仍须保留原 S0 的有效证据和完整定义；不能把较简单父项静默代入原组合名称。

## 4. A3：组合、归因与收敛

按已登记顺序消费 `S0_G0`（只有准入时）、`S0_P2`、`S0_P10`。后两项为一次性有限诊断，保留真实负结果，不是给已失败 P10 新部署机会。

每个组合必须同时提供固定 R0、全部实际父方案及 incumbent 的比较。重点四项对照分别是：

| 主要变更 | 必备共同对照 |
|---|---|
| S 与时间分组方向规则 | R0、S0、G0、S0_G0 |
| S 与 dp2 | R0、S0、P2、S0_P2 |
| S 与 dp10 | R0、S0、P10、S0_P10 |

S0_G0 只有相对 R0 与 incumbent 全保护且有严格主要收益，才更新 incumbent；同时报告与 S0、G0 的完整关系。若组合无收益或退化，保留各父项原有结论，不自动一并淘汰。不得把“比 R0 好”写成“组合比 S0 好”。

去除组件直接使用已存在的对应父项：S0_G0→S0 是移除时间分组规则，S0_G0→G0 是移除整组 S 放宽；S0_P2/P10→S0 是移除 P 变体；S0→S_POINTS2 或 S_LENGTH0 是移除一个过滤放宽项。只对完整读数等价的移除使用简化决策；有实际主要损失时保留具有贡献的成分。无需为组件数制造目标，也不生成未登记组合。

三项计划比较已经有完整实际对照或真实未准入原因后，A 做一次剩余机会复盘。当前已知方向退化、P 同预算压缩缺口、额外删除保护缺依据以及已危险顺序均有具体处理，不强制凑 3 轮空实验。没有新证据支持的范围内假设时，登记 `CONVERGED_WITHIN_REGISTERED_SCOPE` 并进入短名单冻结。只有实际新故障属于工程错误才继续修复；合法负结果不修到胜出。

## 5. P 专项拒绝与组件准入

P 专项比较键固定为 `P2|R0、P10|R0、S0_P2|S0、S0_P10|S0`，逐记录审核。以下任一项成立即禁止把 P 变体作为发布改进：

- 完整 P 输入的记录/片段/原始索引、值或顺序不同：`DP_REFERENCE_CHANGED`，不能计算可比压缩收益。
- 同一实际 P 输入到即时输出的任何误差超过 `5 + 固定数值余量`：`COMMON_DP_BUDGET_EXCEEDED`。候选自己的阈值为 10 不使该条件失效。
- 原始断点、首尾或共同覆盖保护失败，或产物工程核验失败：按实际原因拒绝/修复。
- 以上全部通过，但相同完整范围的 P 即时输出总点数未至少少 1：`NO_DEMONSTRATED_P_COMPRESSION_GAIN`。不能用更小自身误差、更多保留点或 S 带来的覆盖增长代替该项。

涉及 P 的组合还要独立满足整链相对 R0 与 incumbent 的 S/D 保护，P 专项不能替代整链读数。零 P 输入的记录保留分母并记不可用；无输入不能被记为零误差或优胜。P2/P10 及其组合在本首轮计划中为诊断对象，不自动加入选择短名单；若出现与确定性 DP 性质不符的“少点且不超预算”结果，先按原始区间和源码定位工程/解释问题，不立刻宣布新算法收益。

## 6. 等价、模块数与可重复并列次序

“增强模块”按可独立移除的已登记修改计，不等同于“新增候选定义数”。点数过滤放宽、长度过滤放宽、一个方向规则、一个 P 阈值改变分别各 1；G0 的诊断条件与其组内 direction 值共同组成一个规则。全部候选新增在线模型依赖为 `false`。

| canonical ID | 增强模块数 | 相对 R0 主要配置差异 | 在线模型 |
|---|---:|---|---|
| R0 | 0 | 无 | false |
| S_POINTS2 | 1 | min_points=2 | false |
| S_LENGTH0 | 1 | min_length=0 | false |
| S0 | 2 | min_points=2；min_length=0 | false |
| D60 | 1 | direction=60 | false |
| P2 | 1 | dp=2 | false |
| P10 | 1 | dp=10，仅诊断 | false |
| G0 | 1 | 原始时间2组方向规则 | false |
| S0_G0 | 3 | S两项放宽 + G0规则 | false |
| S0_P2 | 3 | S两项放宽 + dp2 | false |
| S0_P10 | 3 | S两项放宽 + dp10，仅诊断 | false |

只有完整范围逐记录读数等价时，才比较 `(enhancement_modules, online_model_dependency, measured_seconds, canonical_id)`。等价要求覆盖身份完全相同、逐点共同误差在固定余量内相等、输入/最终/过滤/方向删除/DP删除/P输入输出及窗口覆盖等已登记计数相同；只比较总均值不足以判定等价。

`measured_seconds` 仅可来自同范围、同运行结构下可归属于该完整策略的实际处理成本。不能把全批混合的 wall time、独立 C 的审核耗时或模型治理时间当成单策略在线成本；共享配置重用也要说明。当前没有可比逐策略计时时，所有缺失值均为 `unknown`，排序时作同值 `+∞`，再用稳定 canonical ID；不填 0、不凭估计宣布较快。成本不可在非等价权衡中推翻 incumbent。模块数最多 3，与当前批准深度上限一致。

## 7. 至多 4 项短名单与打开选择集的门槛

正常的预登记短名单次序是 `R0 → S0 → G0 → S0_G0`，只保留各项当前有效且满足准入的定义；R0 必留，组合不存在或未准入则减少条目，不凑满 4 项。R0 是预定安全回退而非最优结论。D60、P2、P10 与两个 P 组合保持诊断身份，不进入本轮发布候选。

如果 A1 的真实去除组件检查确认 S0 与已登记的 S_POINTS2 或 S_LENGTH0 完全等价，允许以该较简单父项占据同一个 S 分支席位，并在冻结中写明实际 canonical ID、完整参数及替换证据；这不是新增候选，不增加席位。不能把替换分支的定义套进未改变名称的 S0_G0；组合仍按其原定义与实际父项证据审核。没有等价证据就不得替换这一席位。

冻结必须在读取任何 G3_SELECTION 方法结果前完成，绑定实际短名单、固定顺序、全部参数/规则、可比成本取值、代码/合同/分区/记忆哈希及保守规则。选择集先核验完整每策略 240 条，然后从 R0 按冻结次序应用“固定 R0 与当前 incumbent 双保护 + 至少一项严格收益”；不可比较保持已通过的 incumbent。不能按返回先后重排，也不能由模型语言打分。

完整逐记录配对和非支配关系全部交付，即使候选未被采用。最多 4 项是上限，不是必须包含 4 项；已有解释充分时不能为了填位复活拒绝候选。

FINAL_CONFIRM 不属于本接口的 A 开发上下文。选择后由主线程冻结主方案、R0与必要只读父项，再执行预先发布门控；A 不读取最终反馈生成新候选。外部确认不支持新方案时采用预定 R0，不在相同最终集调参。

## 8. A 的返回结构与当前状态

每轮返回 `target_run_id/hash、checked_scope、engineering_receipt_ref、candidate_status、fixed_reference_comparison、incumbent_comparison、parent_comparisons、P_component_gate、decision_rule_id、previous/next_incumbent、unused_or_rejected_reason、remaining_task_ids`。附完整失败记录清单/证据路径、实际计数和新增覆盖读数；没有被审核的字段列入 `unchecked`。

当前本文件只固定结果消费接口；尚未读取新 G3 开发结果、选择效果或最终确认效果，没有触发候选接受、撤回或最终赢家裁决。
