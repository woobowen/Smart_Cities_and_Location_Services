# 5. 实验研究方式：动态演化，而不是固定脚本

- 各算法耗时；
- CPU 与内存；
- 实验规模；

# 7. 评价体系：正确执行不等于效果优秀

建立三层评价。

## 第一层：实现正确性

算法是否按定义执行。

## 第二层：比较可信性

结果是否来自共同、合理、独立的参考条件。

## 第三层：实际效果

在约束满足时，方法是否提供有价值的改善。

关键指标根据任务至少覆盖：

### 在线匹配

- 匹配数量；
- 匹配率；
- 未匹配数量；
- 平均延迟；
- 最大延迟；
- 等待与行驶的延迟分解；
- 尾部分位数；
- 合法竞争比；
- 运行成本。

### 多目标优化

- Pareto 前沿；
- HV；
- Spacing；
- 目标范围；
- 非支配解数量；
- 前沿覆盖；
- 重复波动；
- 目标函数评价次数；
- 实际耗时。

### 强化学习

- 总收入；
- 应答率；
- 已完成订单；
- 平均接驾距离；
- 司机空驶成本；
- TD 误差；
- 训练稳定性；
- 拒单行为；
- 不同时段和车队规模的差异。

不得把匹配率、接驾距离、收入和公平性无依据地合成为一个临时“综合质量分”。

不同指标发生冲突时，应解释 Pareto 权衡或业务约束，不能随意改权重宣布一个方案全面最优。

无匹配、无可计算数据或不可行情况，必须保留明确状态，不能填零后使其获得虚假优势。

重要比较应报告统计单位、样本数、分母、重复次数和不确定性。

# 8. 研究优化循环：必须真正推动下一轮实验

建立两个互补的循环。

## 8.1 工程修复循环

`实现 → 检查 → 缺陷复现 → 最小修复 → 专项测试 → 独立回归 → 旧结果失效 → 重算 → 恢复父任务`

发现 bug 后不能只修改代码而继续使用旧指标、旧图表和旧报告结论。

## 8.2 研究优化循环

`真实结果 → 问题定位 → 机制假设 → 新实验 → 可信比较 → 采用 / 修改 / 拒绝 / 回退 → 下一轮`

对每个有价值的负结果，分析是否来自：

- 数据；
- 模型假设；
- 参数；
- 算法机制；
- 仿真约束；
- 计算预算；
- 随机性；
- 评价方法；
- 实现错误。

不能把负结果自动归因于参数不好，也不能为追求正结果无限搜索。

优化效果可以表现为：

- 方法质量改善；
- 约束违反减少；
- 最差体验改善；
- 对场景差异的理解更充分；
- 评价漏洞被修复；
- 找到稳定的适用区域；
- 发现复杂方法无新增收益并回退；
- 以更低成本得到可比结果。

不是所有循环都必须带来指标上涨。

对真正有效的优化，应保留实际增益和代价；对无法证明改进的候选，保留如实结论。
